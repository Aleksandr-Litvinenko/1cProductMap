# Как заявки попадают в Битрикс24

Браузер отправляет заявку на наш сервер. Сервер своим ключом создаёт лид методом
`crm.lead.add` и получает его номер.

```
браузер ──POST /api/lead──▶ nginx ──proxy──▶ сервис приёма ──crm.lead.add──▶ Битрикс24
   JSON                    map.product1c.ru   127.0.0.1:8123                  лид № 8045
```

## Почему заявка идёт через свой сервис

Первая версия отправляла заявку в точку приёма CRM-формы `crm.site.form.fill`, и
лиды создавались пустыми. Причин было три.

1. Форма в Битриксе настроена как форма заказа с оплатой. Ответ содержит
   `"pay":true` и ссылку на оформление заказа, то есть форма ждёт товарную корзину.
2. Точка приёма не документирована и не проверяет данные. На неверные имена полей,
   неверные типы и лишние поля она отвечает «успех», поэтому проверить, дошли ли
   данные, нельзя.
3. Когда форму правили, прежние поля (`CONTACT_NAME`, `CONTACT_EMAIL`) пропали, и
   код об этом не узнал, потому что ошибок точка приёма не возвращает.

Метод `crm.lead.add` документирован, поля в нём называются явно, а в ответ
приходит номер созданного лида, по которому результат можно проверить.

## Ключ доступа

Нужен входящий вебхук с правом CRM: Битрикс24 → Приложения → Разработчикам →
Другое → Входящий вебхук. Адрес вебхука выглядит так:

```
https://<портал>.bitrix24.ru/rest/<id>/<токен>/
```

Вебхук даёт доступ ко всей CRM, поэтому в коде и в git его нет. Он лежит в файле
на сервере:

```
/etc/karta1c/bitrix-webhook   права 600, владелец root
```

Сервис читает файл при каждом запросе. Чтобы заменить ключ, достаточно
перезаписать файл и перезапустить юнит. В логи и ответы API ключ не попадает,
пишутся только номер лида и адрес отправителя.

Если ключ попал в переписку или тикет, выпустите в Битриксе новый и замените файл.
Старый перестаёт работать сразу.

## Что уходит в лид

| Поле Битрикса | Откуда |
|---|---|
| `TITLE` | «Карта 1С — комплект» или «Карта 1С — <название продукта>» |
| `NAME` | имя из формы |
| `PHONE` | телефон из формы |
| `EMAIL` | почта, если заполнена |
| `IM` | мессенджер, если заполнен |
| `COMMENTS` | состав комплекта, суммы, расчёт мест, оговорки, комментарий клиента и построчная расшифровка цен |
| `SOURCE_ID` | `WEB` |
| `SOURCE_DESCRIPTION` | «Карта продуктов 1С» |

Пример комментария:

```
Конфигурации: 1С:Бухгалтерия
Рабочие места: 1 место уже в поставках, докупаем 9, всего 11 мест на 10 человек.
Разовая покупка: 83 900 ₽
Статус расчёта: предварительный, требует подтверждения специалистом
Размер компании: 10 чел.

─── ПОДРОБНЫЙ РАСЧЁТ ───
Разовая покупка:
  1С:Бухгалтерия · ПРОФ — 23 000 ₽
  Лицензии ПРОФ ещё на 9 мест — 60 900 ₽
  ИТОГО РАЗОВО: 83 900 ₽

Рабочих мест в расчёте: 10, лицензии ПРОФ.
Рекомендованные розничные цены на 8 августа 2026. Внедрение и скидки не учтены.

Источник: map.product1c.ru
```

## Сервис приёма

Небольшой сервис на стандартной библиотеке Python. Он слушает только `127.0.0.1`,
снаружи до него можно достучаться лишь через nginx по пути `/api/lead`.

| Что | Где |
|---|---|
| Юнит | `karta1c-lead.service` |
| Ключ | `/etc/karta1c/bitrix-webhook` |
| Лог | `/var/log/karta1c-lead.log` |
| Проверка | `GET /api/lead/health` |

Сервис принимает не больше 12 заявок с одного адреса за 10 минут, отсекает ботов
скрытым полем-ловушкой, ограничивает размер запроса и требует имя и телефон.

```bash
curl -s https://map.product1c.ru/api/lead/health
# {"ok":true,"configured":true} — сервис работает и ключ на месте
```

Ответ `"configured": false` означает, что файла с ключом нет и заявки уйдут по
запасному пути.

## Запасной путь

Если сервис недоступен, форма отправляет заявку в точку приёма CRM-формы. Лид
создастся, но беднее: полей «Имя» и «E-mail» в форме может не быть, и всё окажется
в комментарии. Этот путь нужен, чтобы заявка не потерялась.
