# Проверка карточек

Список «Самопроверка перед публикацией» из [card-structure.md](card-structure.md)
удобен, пока карточек десяток. На 46 карточках руками его никто не проходит —
поэтому проверки собраны в скрипт.

```bash
python3 scripts/validate_cards.py examples/card.json
```

Зависимостей нет: только Python 3.8+ из коробки. Код возврата `0` — чисто,
`1` — есть ошибки, `2` — файл не прочитался.

---

## Что проверяется

**Обязательные поля.** Все 15 полей из таблицы «Обязательные» на месте.

**Этаж и задачи.** `r` — одно из `conf` / `govconf` / `serv` / `tech` / `host`.
`k` — либо `all`, либо коды задач через запятую **без пробелов**. Пробел после
запятой — частая опечатка, которая тихо выкидывает карточку из задачи.

**Размер компании.** `min` и `max` — целые числа в диапазоне 1..10000,
и `min` не больше `max`.

**Длины текстов.** Подзаголовок `f` — до 60 знаков и без точки в конце.
«Простыми словами» — от 40 знаков: заглушка в одно слово не проходит.
Полный список границ — в [`schemas/card.schema.json`](../schemas/card.schema.json).

**Количество пунктов.** `g` — 1–4, `b` — 1–3. Пустой массив `b` — ошибка:
честное «не берите, если» обязательно, это правило проекта, а не украшение.

**Редакции.** Если поле `ed` есть, редакций должно быть минимум две — одна
редакция не заводится отдельным блоком. У каждой проверяются `n`, `sc`, `t`,
`d`, `y`, `n2`.

**Уникальность `id`.** Два одинаковых кода — вторая карточка молча затирает первую.

**Ссылочная целостность.** Каждый `id` в `COMPOSITE` и каждый ключ `FULL`
существуют среди карточек. Это ловит самую неприятную ошибку каталога: опечатка
в `COMPOSITE` не роняет страницу, карточка просто беззвучно выпадает из комплекта.

---

## Что выдаётся предупреждением, а не ошибкой

Предупреждения не влияют на код возврата, их можно скрыть флагом `--quiet`.

- Неизвестное поле в карточке — скорее всего опечатка в имени.
- Этаж `tech` или `host` без `k:"all"` и без `cv:"ck"` — по правилам эти этажи
  не привязаны к задаче и красятся нейтральным серым, но исключения бывают.

## Формат входного файла

Принимается либо массив карточек:

```json
[ { "r": "conf", "id": "bp", "...": "..." } ]
```

либо объект целого каталога — тогда дополнительно проверяются ссылки:

```json
{
  "ITEMS": [ { "...": "..." } ],
  "FULL": { "bp": "1С:Бухгалтерия 8" },
  "COMPOSITE": { "allsmall": ["unf", "bp"] }
}
```

Ключи, начинающиеся с подчёркивания, игнорируются — в них удобно держать
комментарии, как в [`examples/card.json`](../examples/card.json).

---

## Схема

[`schemas/card.schema.json`](../schemas/card.schema.json) — та же структура
в формате JSON Schema draft-07. Скрипт её не читает (он самодостаточен), но схему
понимают редакторы: VS Code с ней подсказывает поля и подсвечивает ошибки прямо
при наборе. Подключается через `$schema` в файле каталога или через настройку
`json.schemas` в рабочей области.

При изменении набора полей правьте оба файла — схему и скрипт.
