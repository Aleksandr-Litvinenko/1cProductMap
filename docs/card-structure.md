# Структура карточки

Весь контент навигатора лежит в одном массиве `ITEMS` внутри файла продукта.
Одна карточка = один объект в этом массиве. Ничего, кроме этого массива и трёх
справочников рядом (`TASKS`, `ROWS`, `FULL`), заполнять не нужно.

---

## Скелет карточки

```js
{
  r:"conf",                       // этаж
  k:"acc",                        // к каким задачам относится
  id:"bp",                        // уникальный код
  c:"1С:Бухгалтерия",             // короткое название на карточке
  f:"Учёт, налоги и отчётность",  // подзаголовок, одна строка
  min:1, max:5000,                // размер компании: от и до, в людях

  w:"Любой компании, которая обязана вести учёт и сдавать отчётность.",
  simple:"Базовая программа линейки: проводки, налоги, вся обязательная отчётность…",
  d:"Регламентированный учёт: план счетов, первичные документы, расчёт налогов…",

  g:["нужно вести учёт по российским правилам","нужно сдавать отчётность"],
  b:["учёт полностью отдан на аутсорс и вам не нужна своя база"],

  ed:[ /* редакции, если есть — см. ниже */ ],

  dep:"коробка · сервер · облако",
  its:"да",
  st:"актуальна"
}
```

---

## Поля по одному

### Обязательные

| Поле | Тип | Что это | Правила |
|---|---|---|---|
| `r` | строка | **Этаж.** Одно из: `conf`, `govconf`, `serv`, `tech`, `host` | см. таблицу этажей ниже |
| `k` | строка | **Задачи**, к которым относится карточка. Несколько — через запятую без пробелов: `"acc,trade"`. Значение `"all"` = показывать в любой задаче | коды задач — см. ниже |
| `id` | строка | **Уникальный код.** Латиница, без пробелов | не менять после публикации: на него ссылаются комплекты |
| `c` | строка | **Короткое название** — то, что видно на карточке | 1–3 слова. `1С:УТ`, а не `1С:Управление торговлей 8` |
| `f` | строка | **Подзаголовок** — что это одной строкой | до ~45 знаков, без точки в конце |
| `min` / `max` | число | **Размер компании в людях**, для которого продукт осмыслен | если подходит всем — `min:1, max:10000` |
| `w` | строка | **Кому это нужно** — одно предложение | начинается с того, кому, а не с того, что умеет |
| `simple` | строка | **«Простыми словами»** — главный текст карточки | 2–4 предложения, без терминов. Подробнее в [content-guide](content-guide.md) |
| `d` | строка | **Подробное описание** — для страницы продукта | 1–3 предложения, здесь термины уже допустимы |
| `g` | массив строк | **«Берите, если»** | 1–4 пункта, каждый — ситуация клиента, а не функция |
| `b` | массив строк | **«Не берите, если»** | 1–3 пункта. Обязательно: честность здесь работает на доверие |
| `dep` | строка | **Как поставляется** | `коробка · сервер · облако`, `сервис · подписка`, `подписка` |
| `its` | строка | **Входит ли в ИТС** | `да` / `нет` / `частично` / произвольная короткая строка |
| `st` | строка | **Статус** | `актуальна`, `актуален`, `снята с продажи`, `обязателен по закону` |

### Необязательные

| Поле | Тип | Что это | Когда ставить |
|---|---|---|---|
| `ed` | массив | **Редакции** продукта: базовая, ПРОФ, КОРП | если у продукта больше одной редакции |
| `partner` | строка | **Разработчик-партнёр** | если продукт делает не фирма «1С». Например `"СКБ Контур"` |
| `note` | строка | **Уточняющая сноска** на странице продукта | когда нужно развести похожие продукты |
| `cv` | строка | **Цвет карточки** вручную | только для нейтральных этажей: `cv:"ck"` |
| `legacy` | `1` | **Снят с продажи** — название зачёркивается | для устаревших продуктов |

## Редакции (`ed`)

Не заводите ПРОФ и КОРП отдельными карточками — это путает.
Одна карточка на продукт, редакции внутри.

```js
ed:[
  { n:"ПРОФ",                                  // название редакции
    sc:"20–500 чел.",                          // размер компании
    t:"Расчёт зарплаты и кадровый учёт",       // что закрывает, одной строкой
    d:"Все начисления и удержания, графики…",  // абзац описания
    y:["нужен корректный расчёт", "…"],        // берите, если
    n2:["мотивация завязана на показатели"] }, // не берите, если
  { n:"КОРП", sc:"200+ чел.", … }
]
```

На карточке при этом автоматически появляется пометка «2 редакции» / «3 редакции» —
руками её писать не надо.

## Справочник этажей

| Код | Этаж | Что кладём |
|---|---|---|
| `conf` | Конфигурации | основные программы учёта: Бухгалтерия, УТ, ERP… |
| `govconf` | Государственные конфигурации | БГУ, ЗКГУ, Свод отчётов, ГМЗ |
| `serv` | Сервисы 1С | подключаются к конфигурации: ЭДО, Отчётность, ОФД… |
| `tech` | Вспомогательные сервисы | технологические, для ИТ-службы: Шина, ЦУП, КД… |
| `host` | Размещение | коробка, сервер, Фреш, ГРМ, аренда, Линк |

Для `tech` и `host` ставьте `k:"all"` и `cv:"ck"` — они не привязаны к задаче
и красятся нейтральным серым.

---

## Справочник задач

| Код | Задача |
|---|---|
| `acc` | Считать деньги и сдавать отчётность |
| `trade` | Продавать и вести склад |
| `hr` | Платить зарплату и вести кадры |
| `mfg` | Производить продукцию |
| `doc` | Согласовывать документы |
| `group` | Управлять группой компаний |
| `gov` | Вести учёт в бюджетном учреждении |

Плюс две комплексные — `allsmall` и `allbig`. Они собираются **не** через поле `k`,
а списком идентификаторов в `COMPOSITE`:

```js
const COMPOSITE = {
  allsmall:["unf","rozn","bp","zup","otch", …],
  allbig:  ["ka","erp","erpuh","uh","zup", …],
};
```

Так один продукт попадает в комплексный набор без засорения его поля `k`.

## Полное название (`FULL`)

Короткое имя живёт на карточке, полное официальное — на странице продукта.
Второе задаётся отдельной таблицей по `id`:

```js
const FULL = {
  bp:"1С:Бухгалтерия 8",
  ut:"1С:Управление торговлей 8",
  zkgu:"1С:Зарплата и кадры государственного учреждения 8",
  …
};
```

Если полное и короткое совпадают, строку можно не заводить — блок просто не покажется.

## Как добавить карточку: порядок действий

1. Придумайте `id` — короткий, латиницей, уникальный.
2. Определите этаж `r` и задачи `k`.
3. **Проверьте каноническое название по официальной странице продукта.** Это
   самый частый источник ошибок: у «1С:Зарплата и кадры государственного учреждения»
   раньше было другое имя, и устаревшее до сих пор гуляет по интернету.
4. Заполните обязательные поля. Тексты — по [content-guide](content-guide.md).
5. Если есть редакции — заполните `ed` вместо создания отдельных карточек.
6. Если разработчик не фирма «1С» — поставьте `partner`.
7. Добавьте полное название в `FULL`.
8. Если карточка должна попасть в комплексный набор — впишите её `id` в `COMPOSITE`.

---

## Самопроверка перед публикацией

- [ ] `id` уникален и не совпадает ни с одним существующим
- [ ] каноническое название сверено с официальной страницей продукта
- [ ] `min`/`max` заданы осмысленно, а не «на глаз»
- [ ] в `b` («не берите, если») есть хотя бы один честный пункт
- [ ] тексты написаны своими словами, а не скопированы с сайтов 1С
- [ ] если разработчик — партнёр, поле `partner` заполнено
- [ ] полное название добавлено в `FULL`
- [ ] все `id` в `COMPOSITE` существуют (иначе карточка молча выпадет из набора)
